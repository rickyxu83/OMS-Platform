# 考勤审批流程适配设计

## 目标

将现有固定的“主管 → 行政终审”考勤审批流程调整为按申请类型和实际工作日数分支的流程，并补齐代理人签核、证明附件、人事签核和副总签核记录。

本设计覆盖请假、调休和加班申请。所属处／单位资料及跨单位代理校验明确延期，待取得组织数据后接入。

## 已确认业务规则

### 假期类别

- 特休，沿用内部值 `annual`，管理端显示名称由“年假”调整为“特休”。
- 事假 `personal`。
- 病假 `sick`。
- 婚假 `marriage`。
- 丧假 `bereavement`。
- 调休 `comp_time` 继续作为独立申请类型。

### 工作日计算

- 一天为 8 小时，半天为 4 小时。
- 周六、周日不计入请假或调休天数。
- 系统中启用的法定节假日不计入请假或调休天数。
- 非工作日夹在申请日期范围中间时不打断工作日累计。
- 例如周五至下周二申请，排除周六、周日后按周五、周一、周二共 3 个工作日计算。
- 达到 3 个工作日，即累计达到 24 个有效申请小时，进入人事和副总审批。
- 申请范围内没有任何有效工作时段时拒绝提交。

### 代理人

- 所有请假和调休申请必须指定代理人。
- 申请人不能选择自己作为代理人。
- 代理人必须是启用考勤的有效员工。
- 加班申请不需要代理人。
- 代理人不允许跨单位，但本期不增加组织单位资料，也不执行跨单位校验；数据结构和审批逻辑不得妨碍后续增加该校验。

### 证明附件

- 病假、婚假必须至少上传一份证明文件后才能正式提交。
- 特休、事假、丧假和调休不强制证明文件。
- 证明文件复用项目现有文件存储机制，归属考勤申请并使用专用用途标识。

### 审批流程

少于 3 个工作日的请假或调休：

```text
申请人提交 → 代理人签核 → 主管签核 → 审批完成
```

达到 3 个工作日的请假或调休：

```text
申请人提交 → 代理人签核 → 主管签核 → 人事签核 → 副总签核 → 审批完成
```

加班费或加班转调休：

```text
申请人提交电子申报表 → 主管签核 → 人事签核 → 审批完成
```

角色映射：

- 人事节点对应 `administrative_supervisor`（行政主管）角色。
- 副总节点对应 `operations_director`（运营负责人）角色。
- `admin` 保留系统管理和异常处置能力，并可执行人事、副总节点审批。

## 技术方案

### 方案选择

采用“申请主表保留当前状态 + 独立审批步骤表”的混合方案。

不继续把所有审批人字段平铺到 `attendance_requests`，因为代理人、主管、人事和副总已经形成可变步骤链，继续扩字段会让查询、驳回和审计逻辑越来越分散。也不引入通用工作流引擎，避免超出当前考勤模块范围。

### 申请主表

在 `attendance_requests` 增加：

- `workflow_version`：旧记录为 1，新流程为 2。
- `delegate_employee_id`：请假或调休指定的代理人员工档案 ID，加班为空。
- `working_days`：后端计算并保存的有效工作日数，支持半天。

现有 `status` 继续作为列表筛选和页面展示使用。新版状态包括：

- `draft`
- `pending_delegate`
- `pending_supervisor`
- `pending_hr`
- `pending_vp`
- `approved`
- `rejected`
- `withdrawn`
- `voided`

### 审批步骤表

新增 `attendance_request_approvals`，每一行代表一个审批步骤，至少包含：

- 申请 ID。
- 步骤类型：`delegate`、`supervisor`、`hr`、`vp`。
- 步骤顺序。
- 指定员工 ID，可为空。
- 指定角色，可为空。
- 状态：`waiting`、`pending`、`approved`、`rejected`、`skipped`。
- 实际审批用户 ID。
- 审批时间。
- 驳回原因。
- 创建、更新时间。

代理人步骤使用指定员工 ID 校验；主管步骤沿用当前申请人角色到主管角色的配置；人事和副总步骤分别使用行政主管、运营负责人角色校验。

正式提交时一次性生成该申请需要的全部步骤：首个步骤为 `pending`，后续步骤为 `waiting`。当前步骤通过后，将下一步骤改为 `pending` 并同步申请主表状态；最后一步通过后将申请标记为 `approved` 并执行余额入账或扣减。

### 旧流程兼容

- 部署前已有申请保持 `workflow_version = 1`。
- 历史已完成记录不补造审批步骤。
- 部署前仍处于 `pending_supervisor` 或 `pending_admin` 的申请继续使用旧主管、行政终审接口和字段，避免因缺少代理人而无法继续。
- 部署后的新申请全部使用 `workflow_version = 2`。
- 列表同时兼容旧审批时间字段和新版审批步骤数据。

## 工作日计算

后端提供唯一权威计算函数，根据开始、结束半天时段生成日期范围，并排除：

- 周六。
- 周日。
- `attendance_legal_holidays` 中当前启用的日期。

函数返回规范化的开始时间、结束时间、有效小时数和工作日数。客户端提交的小时数不作为审批分支依据，避免篡改；后端按日期时段重新计算。

前端加载法定节假日并使用相同规则显示预览，但提交结果以后端计算为准。

## 证明文件流程

病假和婚假采用“先建立草稿申请，再上传证明，最后正式提交”的流程：

1. 客户端创建 `draft` 状态申请并取得申请 ID。
2. 使用现有文件接口上传文件，`owner_type` 为 `attendance_request`，`owner_id` 为申请 ID，`purpose` 为 `leave_proof`。
3. 客户端调用正式提交接口。
4. 后端确认至少存在一个证明文件后，生成审批步骤并进入 `pending_delegate`。

其他请假、调休和加班也使用相同的草稿提交接口，以保持前端流程一致；没有附件时可在创建草稿后立即提交。

只有申请人可以为自己的草稿上传证明或提交草稿。草稿不进入审批待办、月度报表和余额统计。

## API 调整

新增或调整以下考勤接口：

- 创建申请草稿。
- 正式提交草稿。
- 获取可选代理人列表。
- 代理人通过。
- 主管通过新版流程。
- 人事通过。
- 副总通过。
- 获取申请审批轨迹。
- 统一驳回当前待处理步骤。
- 撤回范围扩展到新版所有未完成状态。

服务端必须在每个审批接口重新校验当前状态和审批人身份，不能仅依赖前端隐藏按钮。

## 管理端调整

- “年假”统一显示为“特休”，内部值保持不变。
- 请假和调休表单增加代理人选择。
- 病假、婚假表单显示必填证明上传区。
- 请假预览显示有效工作日数，并明确周末和法定节假日已排除。
- 待办列表支持代理人、主管、人事和副总四类节点。
- 状态标签增加待代理人、待人事、待副总。
- 申请记录显示审批轨迹，包括步骤、审批角色或人员、结果和时间。
- 加班申请继续使用当前工单派生的纯电子表单，不增加纸质表单或签字文件。
- 所有可见改动同步提升管理端版本号三处配置。

## 权限与安全

- 代理人审批必须验证当前用户对应的员工档案等于步骤指定员工。
- 主管审批沿用现有主管角色规则，但只能处理当前处于主管步骤的申请。
- 人事审批要求 `administrative_supervisor` 角色或管理员权限。
- 副总审批要求 `operations_director` 角色或管理员权限。
- 任何用户不能审批不属于自己的当前步骤。
- 证明文件上传、读取和下载必须校验申请人与审批查看权限。
- 余额变更只允许在最终审批事务中执行一次，重复请求不得重复入账或扣减。

## 测试范围

后端至少覆盖：

- 周五至下周二计算为 3 个工作日。
- 周末和启用的法定节假日被排除。
- 2.5 个工作日由主管终审。
- 3 个工作日进入人事和副总流程。
- 请假、调休缺少代理人时拒绝提交。
- 申请人不能选择自己为代理人。
- 病假、婚假缺少证明时拒绝正式提交。
- 丧假没有证明仍可提交。
- 非指定代理人不能审批。
- 非行政主管不能执行人事审批。
- 非运营负责人不能执行副总审批。
- 加班经主管、人事后完成，不生成代理人和副总步骤。
- 旧版待审批记录仍可按旧流程完成。
- 最终审批重复调用不会重复修改余额。

前端验证包括 TypeScript 编译和生产构建，并人工检查申请表单、待办操作、状态标签和审批轨迹。

## 本期不包含

- 所属处／单位字段。
- 跨单位代理校验。
- 通用组织架构管理。
- 纸质加班申报表、手写签名或 PDF 签核单。
- 与本次审批规则无关的考勤制度扩展。
