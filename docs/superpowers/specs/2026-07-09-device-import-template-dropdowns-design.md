# 设备导入模板维保下拉设计

## 背景

设备资产批量导入模板由管理端 `Devices.tsx` 使用 ExcelJS 动态生成。后端导入接口已经支持识别维保类型中文文本，并会按“维保类型 + 维保方名称”匹配 `maintenance_parties` 表。

## 目标

- 在设备导入模板中为“维保类型”列提供 Excel 下拉菜单。
- 在设备导入模板中为“维保方名称”列提供 Excel 下拉菜单。
- 每次用户重新下载模板时，从系统维保方目录读取最新名称，写入模板下拉名单。
- 不改变设备型号、n-cloud 等设备数据的现有导入和纠正规则。

## 非目标

- 不让已经下载到本地的旧模板自动更新。
- 不实现按维保类型联动过滤维保方名称。
- 不自动创建不存在的维保方。

## 数据流

1. 用户点击“下载导入模板”。
2. 前端调用现有 `/maintenance-parties` 接口读取维保方目录。
3. 前端生成 Excel 模板。
4. 模板中新增隐藏数据表，保存维保类型和去重后的维保方名称。
5. 主模板对“维保类型”和“维保方名称”两列添加数据验证，下拉范围覆盖后端允许的 1000 行导入上限。

## 行为细节

- 维保类型下拉值为：`待确认`、`无维保`、`原厂维保`、`我方维保`。
- 维保方名称从接口返回的 `items[].name` 提取，去空、去重、按名称排序。
- 如果维保方目录为空，模板仍可下载，维保方名称列不设置下拉或仅保留字段说明。
- 如果维保方目录读取失败，模板下载失败并展示错误，避免用户误以为拿到的是最新模板。
- 后端导入校验保持不变：有维保方名称时仍必须能按维保类型匹配已有维保方。

## 验证

- 前端 TypeScript 检查通过。
- 管理端构建通过。
- 手动或脚本检查下载模板的 Excel 数据验证存在：
  - “维保类型”列带下拉。
  - “维保方名称”列带数据库维保方名称下拉。
  - 隐藏数据表不影响主模板填写。
