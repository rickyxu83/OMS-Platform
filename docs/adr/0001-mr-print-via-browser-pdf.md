# MR 存档文件用「网页打印页 + 浏览器存 PDF」，不在后端生成 PDF

MR 单审批通过后需要一个可打印的存档文件（沿用 Excel 宏 `ExportMRPDF` 的自动排版效果：只显示选中的选项、品名/原厂规格折行、浅色表头）。决定在 frontend-admin 内做一张专用打印排版页，用户浏览器 Ctrl+P 存 PDF，而不是后端用 puppeteer/playwright 渲染。

原因：OMS 后端是轻量 Node + Docker，为导出 PDF 引入浏览器运行时代价高；网页打印页所见即所得、无新增依赖，Mac/Windows 桌面浏览器均可用。Excel 导出宏的排版规则（选项过滤、折行、表头配色）在前端打印 CSS 中复刻。

代价：打印效果依赖浏览器排版引擎，跨浏览器存在细微差异；不满足时再评估服务端渲染。
