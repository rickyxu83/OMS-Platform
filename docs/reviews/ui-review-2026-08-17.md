# 管理端 UI 设计审查报告（2026-08-17）

> 范围：frontend-admin 全部 19 个页面 + AdminLayout + 设计 tokens + ui 组件库 + packages/mr。
> 方法：对照 Vercel Web Interface Guidelines 静态通读全部源码。

## 一、总体印象

底子很好，远超一般内部系统：

- 完整设计 token 体系（violet `#7c3aed` + Inter/Noto Sans SC），圆角/阴影/间距统一
- 骨架屏、三点按钮 loader（`btn-loader`）、列表行入场动画、路由转场（PUSH/POP 区分方向）
- 测试服黄色横幅、简繁切换、公告弹窗、权限驱动导航、版本号展示、考勤/待办计数徽标
- ServiceReport 移动端 sticky 顶栏（下滑隐藏）+ 底部 sticky 操作栏带 `safe-area`、电子签署链接+二维码+邮件
- MR 模块的 `SectionNav`（分区导航 + 每区校验错误计数徽章）是全站最佳实践
- 列表页模式高度统一：统计卡 + 筛选卡 + `62vh` 定高表格 + sticky 表头 + 行可键盘操作
- 删除类操作有影响面确认弹窗；表格筛选状态部分页面同步 URL（ServiceOrders 是标杆）

## 二、问题清单

### A. 一致性 / 品牌（美化向）

| # | 问题 | 位置 |
|---|------|------|
| A1 | **双紫色品牌不统一**：登录页整套用 `#582B8B`（深紫），进系统后 primary 是 `#7c3aed`（亮紫），用户感知像两个产品 | `pages/Login.tsx`（十余处硬编码）vs `styles/theme.css:21` |
| A2 | **整个 antd 仅为一个 TimePicker**：桌面端动态 `import("antd")`，视觉（antd 默认蓝系）与自研 violet 体系不统一，依赖体积 600KB+ | `pages/ServiceReport.tsx:668`、`styles/theme.css:249` 补丁样式 |
| A3 | **硬编码 slate/gray 色遍布页面**，绕过 token（`text-slate-N`：Customers 25 处、Devices 24 处等），与 token 中性灰有色差，且未来开暗色模式全挂 | 各列表页 |
| A4 | **`.dark` 完整暗色 tokens 是死代码**：全库无任何切换入口 | `styles/theme.css:56` |
| A5 | **行内操作按钮自创风格** `bg-slate-50 text-slate-900` / 删除用 `bg-red-50 text-red-600`，与 `ui/button` 变体体系不一致 | `pages/ServiceOrders.tsx:1790`、`pages/Customers.tsx:1662` 等 |
| A6 | **i18n 覆盖不均**：Login/Dashboard/AdminLayout/Customers 有完整 zh-TW；Dashboard 预览弹窗 label 与"搜索/重新生成"硬编码简体（`Dashboard.tsx:938,1028,1263` 等）；Attendance/Users/SystemSettings 等页整体只有简体 | 多页面 |

### C. 无障碍 / 规范

- `transition-all`：`components/ui/button.tsx:10`、`AdminLayout.tsx:400`、`Login.tsx` 4 处（指南要求显式列属性）
- 无 `prefers-reduced-motion` 降级的动画：`list-row-enter`、`stat-value-enter`、`btn-loader`、`ai-progress-bar`、测试服横幅 sweep（`globals.css:17-113`、`AdminLayout.tsx:435`）；路由转场已合规 ✓
- 搜索 Input 普遍 placeholder-only 无 `aria-label`（Dashboard/各列表页）
- Radix `Select` 的 `Label` 普遍未关联控件（无 id 转发），Timesheets/新建工单弹窗等
- `div onClick` 仅 7 处且均为 stopPropagation，可接受 ✓
- viewport 未禁缩放 ✓；Skeleton 有 `aria-hidden` ✓；html lang="zh-CN" ✓（切繁体后未同步更新 lang 属性，次要）

### D. 工程结构（影响 UI 演进成本）

- `ServiceReport.tsx` 6189 行、`Devices.tsx` 4659 行、`Customers.tsx` 2485 行单文件，UI 迭代风险高
- `AdminLayout.tsx` 810 行内含大段 STRINGS/NAV 配置，可拆
- `AttendanceDuty.tsx` JSX 压缩成单行风格，审查困难

## 三、优化建议（按优先级）

### P0 — 便宜且立竿见影（1 天内可做完）

1. **统一品牌紫**：建议把全局 `--primary` 定为登录页的 `#582B8B`（更稳重），登录页硬编码色全部改 token；或反向统一为 `#7c3aed`。一色到底。
2. **Toaster 修配**：`theme="light"`，移动端改 `top-center` 或 bottom 偏移避开底栏。
3. **统计数字 `toLocaleString()` 千分位**（所有统计卡一处封装）。
4. **AI 总结按钮图标** Download → `Sparkles`，消除导出误导。
5. **空态统一 `<EmptyState>` 组件**：图标 + 一句人话 + 主行动按钮（如"新建第一张工单"）。
6. **动画补 `prefers-reduced-motion`**（globals.css 一个 media query 全覆盖）。
7. **登录页修边角**：error 加 `role="alert"`、aria-label 中文化、input 加 `name`。
8. **ApprovalTasks 行补键盘支持**（照抄 ServiceOrders 行模式）。

### P1 — 中等工作量，体验跃升

9. **移动端列表卡片化**：抽象 `<ResponsiveList>`，断点以下渲染卡片（复用 Dashboard 最近工单的双套布局思路），操作按钮沉到卡片底部。优先 ServiceOrders / Customers / Devices。
10. **ServiceReport 接入 SectionNav**：复用 MR 的分区导航 + 校验错误计数，长表单有了"目录"。
11. **干掉 antd**：TimePicker 换原生 `input[type=time]` 或自研下拉（移动端本来就走原生），删 `antd`+`dayjs` 依赖，视觉统一。
12. **移动端底部导航扩到 4~5 项**或支持角色化配置（工程师：首页/填写/考勤/我的）。
13. **i18n 收敛**：至少把 Dashboard/ServiceOrders 里硬编码简体收进 STRINGS；其余页面排期补齐。
14. **搜索语义统一**：列表页都走"防抖 + URL 同步"（ServiceOrders 模式），搜索框补 `aria-label`。
15. **ChangePassword 补 autocomplete 与密码可见性切换**。
16. **深色模式决策**：要么删 `.dark` tokens 减维护，要么立 roadmap（前置条件是先收敛硬编码色）。

### P2 — 长期

17. 404 页（带返回首页链接）。
18. ServiceReport/Devices 按 section 拆文件。
19. 公共签署页品牌化：logo、页脚（备案/公司信息）、签署完成独立页。
20. Dashboard 统计卡可加迷你趋势线/环比（纯美化）。

## 四、一句话结论

**设计完成度已经在"好用"水平，主要差距在：移动端表格横滑（B1）、品牌色两套（A1）、长表单缺导航（B4）、antd 混用（A2）。** P0 清单一天内能落，P1 的列表卡片化和 SectionNav 复用是体验跃升点。
