本文檔是 OMS Platform 的完整日常使用說明，適用於管理員、營運負責人、調度、工程主管和現場工程師，覆蓋登入、權限、工單、客戶資產、服務表、離線草稿、報表、隱私和常見問題。

## 1. 產品概覽

OMS Platform 是面向現場運維、售後服務、客戶資產和服務記錄協同的平台。

系統主要分為兩個工作臺：

- **管理工作臺**：供後台和管理角色使用，負責工單派發、客戶與資產維護、巡檢、月報、使用者、審計和系統設定。
- **工程師工作臺**：供工程師使用，負責查看分配任務、查詢客戶資產、填寫服務表、管理離線草稿、查看個人月報、維護資料和簽名。

## 2. 登入與工作臺選擇

1. 打開統一登入頁：`https://<admin-domain>/login`。
2. 輸入帳號和密碼。
3. 如果帳號只有一個可用工作臺，系統會自動進入。
4. 如果帳號擁有多個工作臺，請選擇本次要進入的工作臺。
5. 工程師帳號可能需要先完成改密、資料補充、頭像上傳或手寫簽名等引導流程。
6. 多次登入失敗後，帳號可能會被臨時鎖定，請等待鎖定結束或聯絡管理員。

## 3. 角色與權限

| 角色 | 工程師端 | 管理端 |
|---|---|---|
| `engineer` | 只查看並處理分配給自己或屬於自己的工單 | 不能登入 |
| `engineering_supervisor` | 進入工程師端時按本人任務過濾 | 查看、派發和管理全部工單 |
| `operations_director` | 不能登入 | 按授權模組查看和管理全部工單 |
| `administrative_supervisor` | 不能登入 | 查看管理端業務資料，不可派單、審批、編輯、刪除或改系統設定 |
| `admin` | 不能登入 | 平台全部權限 |

權限會在前端路由和後端介面同時校驗。如果頁面不可見或介面返回無權訪問，請先確認帳號角色和工作臺權限。

## 4. 管理工作臺模組

### 4.1 營運總覽

營運總覽用於快速查看目前服務狀態。

- 查看工單總數、待處理、已完成和異常狀態。
- 查看近期服務活動和工作量分布。
- 根據看板判斷需要派單、催辦或複核的事項。

### 4.2 工單處理

工單用於管理服務生命週期。

常見流程：

1. 根據客戶請求或內部服務需求建立工單。
2. 填寫客戶、聯絡人、站點、設備、問題、優先級和期望服務資訊。
3. 指派工程師或工程主管。
4. 跟蹤處理過程中的狀態變化。
5. 查看工程師提交的服務表和後續說明。
6. 服務完成後關閉或歸檔工單。

建議：

- 派單前先確保客戶和設備資訊準確。
- 問題描述應清晰，便於工程師準備工具、備件和遠端支援資料。
- 對外分享或匯出前，應先複核服務表內容。

### 4.3 客戶與資產

客戶和資產是服務記錄的基礎資料。

- 維護客戶名稱、站點、地址、聯絡人和電話。
- 維護設備型號、序列號、軟體版本、保固資訊和維保方。
- 僅在私有環境檔案配置好地圖 Key 後使用地圖/位置搜尋。
- 新建客戶前先搜尋，避免重複檔案。

### 4.4 設備型號目錄

設備型號目錄用於統一設備型號輸入。

- 支援多關鍵詞和常見別名搜尋。
- 管理員可在準備好新型號資料後同步 fixture 資料。
- 保持型號名稱一致，有助於後續統計和報表分析。

### 4.5 巡檢計畫

巡檢計畫用於計畫性維護任務。

- 為週期性客戶或設備檢查建立計畫。
- 指派負責工程師。
- 跟蹤即將到期、逾期和已完成的巡檢。
- 必要時將巡檢結果轉為服務記錄。

### 4.6 月報與工時

月報用於彙總服務活動和工時。

- 按月份、工程師、客戶或工作類型匯出服務統計。
- 生成正式報表前先檢查缺失或異常記錄。
- 可用於內部結算、績效複核和服務分析。

### 4.7 使用者、角色與審計

- 建立和維護使用者帳號。
- 按實際崗位分配角色。
- 及時停用離職或停用帳號。
- 透過審計日誌追蹤登入、資料修改、匯出和設定變更等敏感操作。

### 4.8 系統設定

根據部署配置，管理員可維護：

- 郵件發送和 SMTP 測試。
- AI 連通性檢測和工作摘要能力。
- 平台級服務參數。

生產密鑰必須放在本地私有環境檔案中，不得提交到 GitHub。

## 5. 工程師工作臺模組

### 5.1 我的任務

工程師透過任務列表查看分配給自己的服務任務。

- 打開任務查看客戶、站點、聯絡人和問題描述。
- 從任務進入服務表，確保服務記錄與工單關聯。
- 如果任務為空，請確認工單是否已分配給本人，以及工程師端是否按本人任務過濾。

### 5.2 客戶資產查詢

服務前可查詢客戶和設備資料。

- 確認站點地址和聯絡人。
- 查看設備型號、序列號、維保方和歷史服務記錄。
- 透過歷史記錄了解是否存在重複故障。

### 5.3 個人資料與簽名

工程師資料會用於服務單。

- 保持姓名、電話、頭像和簽名最新。
- 提交需要簽名的服務表前，應完成簽名引導。
- 僅在授權且必要時更換簽名。

## 6. 服務表完整流程

服務表用於記錄真實服務過程。

1. 打開已分配任務，或選擇 **新建服務表**。
2. 選擇服務類型：現場、遠端或內勤。
3. 選擇客戶、站點、聯絡人和關聯設備。
4. 填寫服務類別、工作性質、支援對象、開始時間和結束時間。
5. 描述故障現象、服務內容、處理步驟、處理結果和後續建議。
6. 必要時填寫備件、附件、照片和工時。
7. 按要求確認工程師簽名和客戶確認。
8. 資訊不完整時保存草稿；複核無誤後提交。
9. 提交後按業務需要分享或匯出服務表。

提交前檢查：

- 客戶和聯絡人是否正確。
- 設備型號和序列號是否正確。
- 時間範圍和工時是否合理。
- 故障和處理結果是否清楚，便於後續追溯。
- 附件中是否包含無關隱私資訊。

## 7. 離線草稿與同步

工程師工作臺支援在網路不穩定時保存本地草稿。

- 填寫服務表時會保存草稿。
- 離線時可繼續使用已有快取資料。
- 網路恢復後，請重新檢查草稿並提交。
- 未確認草稿已提交前，不要清理瀏覽器快取或本地存儲。

## 8. 分享、匯出與報表

- 提交後的服務表可先預覽再分享。
- 匯出的圖片或文檔應檢查是否包含敏感資訊。
- 月報應在當月服務表全部提交後生成。
- 如果報表資料異常，請檢查服務類型、工時、工程師歸屬和是否存在未提交草稿。

## 9. 隱私與資料安全

不得公開或提交以下內容：

- 真實客戶名稱、聯絡人、手機號、郵箱、地址和定位資訊。
- 工單號、服務詳情、故障描述、內部備註和審核意見。
- 設備序列號、資產編號、主機名、IP 地址和保固資訊。
- 未經明確授權的工程師姓名、頭像、手機號和手寫簽名。
- Token、Cookie、密碼、API Key、`.env` 檔案、SSH 目標、遠端目錄、生產域名和部署密鑰。

對外分享截圖前，請使用實心遮罩或馬賽克。若前端地圖 Key 或第三方 Key 曾公開暴露，請立即更換，並在服務商控制台配置域名或 Referer 白名單。

## 10. 常見問題

| 問題 | 建議檢查 |
|---|---|
| 無法登入 | 檢查帳號狀態、密碼、鎖定狀態和後端服務可用性。 |
| 無法進入工作臺 | 確認角色是否擁有對應工作臺權限。 |
| 工程師任務為空 | 確認工單分配和本人任務過濾邏輯。 |
| 服務表無法提交 | 檢查必填項、簽名、網路狀態和附件大小。 |
| 草稿遺失 | 確認未清理瀏覽器存儲，並使用同一設備和瀏覽器。 |
| 地圖搜尋失敗 | 檢查後端地圖 Key 和前端地圖 JS Key 是否配置在私有環境檔案中。 |
| 匯出或分享失敗 | 檢查瀏覽器權限、檔案大小，以及記錄是否已提交。 |
