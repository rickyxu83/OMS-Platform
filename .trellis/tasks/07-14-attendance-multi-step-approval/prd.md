# 考勤多级审批规则

## Goal

考勤设置支持按申请人角色配置有顺序的多级审批链。申请提交后，审批步骤依次激活，前一步通过后才流转到下一步；现有单步规则可以平滑升级，历史申请不受配置变化影响。

## Background

- 当前设置页把每个申请人角色映射到唯一的 `supervisorRole`，界面只能选择一个“提交后由谁处理”的角色。
- 当前数据库表 `attendance_supervisor_role_rules` 以 `applicant_role` 为主键，只能保存一个 `supervisor_role`。
- 新版申请已经通过 `attendance_request_approvals.step_order`、`pending` 和 `waiting` 支持顺序审批，前一步通过后会激活下一步。
- 当前流程生成器仍会根据申请类型和请假天数硬编码追加行政主管、副总等步骤：加班固定追加行政主管；三天及以上的请假或调休会追加行政主管和副总。
- 已确认新的可配置审批链将完全替代上述硬编码角色审批步骤；代理人等非角色业务步骤仍独立保留。
- 已确认同一申请人角色对请假、加班和调休共用一条审批链，不按申请类型分别配置。
- 已确认申请人不能审批自己的申请；审批链包含申请人角色时，只允许同角色的其他人员处理。
- 已确认一个审批角色有多名可用人员时，任意一人审批即可完成该步骤，其他同角色人员不再显示该待办。
- 已确认草稿不锁定审批链，正式提交时使用当时最新规则生成并固化审批步骤。
- 已确认同一审批链中每个审批角色最多出现一次，不支持重复角色复审。
- 已确认管理员不能越权代审任意步骤；只有审批链明确配置管理员角色时，管理员才能处理。
- 申请提交时会生成并保存审批步骤，因此现有 v2 申请已经具备与后续设置变化隔离的基础。
- 历史 `workflow_version = 1` 和当前 `workflow_version = 2` 申请均有既有处理路径，不能因本功能失效。

## Requirements

- 每个申请人角色至少保留一个审批步骤，并支持通过“添加步骤”追加后续审批角色。
- 设置界面必须清楚展示第 1、2、3……级审批顺序，并提供调整顺序和删除步骤的能力，但每条审批链至少保留一步。
- 保存时校验申请人角色和每个审批角色均为有效系统角色，审批链不得为空。
- 保存时拒绝包含重复审批角色的审批链。
- 新提交的申请必须把当时生效的审批链快照写入申请审批步骤；后续修改规则不得改变已提交申请。
- 已创建但未提交的草稿不保存旧审批链；规则变化后按提交时最新规则生成流程。
- 流程生成器不得在配置审批链之后再自动追加行政主管、副总等角色步骤。
- 审批链仅按申请提交时的申请人角色选择，适用于该角色提交的全部考勤申请类型。
- 当前单步配置必须自动兼容为仅含一个步骤的审批链，不要求人工重新配置。
- 各步骤只能由对应角色审批；前一步未通过时，后续角色不能提前审批。
- 管理员遵守与其他角色相同的步骤授权，不得绕过当前审批链代审。
- 生成审批链时必须确认每个角色至少存在一名申请人本人之外的可用审批人；否则阻止提交并明确提示缺少审批人。
- 角色审批步骤采用“任一处理”语义，不要求同角色所有人员会签。
- 任一步驳回后申请立即结束，后续等待步骤不得继续激活。
- 历史申请以及已经生成审批步骤的申请保持原流程。

## Acceptance Criteria

- [ ] 管理员可为“助理”配置“行政主管 → 运营负责人（副总）”两级审批链并保存。
- [ ] 助理提交新申请后，行政主管先看到待审批；行政主管通过后，运营负责人才看到待审批。
- [ ] 运营负责人无法在行政主管通过前审批该申请。
- [ ] 申请人即使具备当前步骤角色，也不能审批自己的申请；同角色其他人员可以审批。
- [ ] 某一步没有申请人之外的可用审批人时，申请不能提交并显示具体缺失角色。
- [ ] 同一角色有多名审批人时，其中一人通过或驳回后，其他同角色人员不能再次处理该步骤。
- [ ] 管理员未被配置为当前步骤角色时，无法通过或驳回该步骤。
- [ ] 任一级驳回后申请状态变为已驳回，后续步骤保持未执行。
- [ ] 原有单步规则升级后行为不变。
- [ ] 修改审批链不会改动修改前已经提交的申请。
- [ ] 规则修改后提交旧草稿时使用最新审批链，而已经提交的申请仍保持原审批链。
- [ ] 配置链中的角色不会因原有请假天数或申请类型规则被重复追加。
- [ ] 同一角色提交请假、加班或调休时生成相同的角色审批步骤。
- [ ] 历史审批申请仍可按原有兼容流程处理。
- [ ] 设置页支持添加、删除和调整步骤顺序，并能阻止保存空审批链或无效角色。
- [ ] 同一审批角色被重复添加时不能保存，并显示明确提示。
- [ ] 后端工作流单元测试与控制器回归测试覆盖单步、多级、越级审批、驳回和历史兼容。

## Out of Scope

- 邮件通知、邮件内同意或拒绝。
- 管理员强制处理、临时改派或跳过进行中的审批步骤。
- 按请假、加班、调休分别配置审批链。
- 同一角色重复出现在一条审批链中的复审流程。
