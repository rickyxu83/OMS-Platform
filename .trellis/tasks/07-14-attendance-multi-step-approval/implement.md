# Implementation Plan: 考勤多级审批规则

1. 在考勤惰性迁移中新增有序审批规则表、唯一约束和从现有单步规则迁移的幂等逻辑。
2. 新增审批链读取与替换接口，完成角色、空链、连续顺序和重复角色校验，并保留旧规则接口。
3. 扩展工作流纯函数，使 v3 根据配置角色数组生成通用角色步骤；代理人步骤保持独立，移除 v3 的申请类型/天数硬编码角色追加。
4. 将草稿提交和工单加班直接申请切换为 `workflow_version = 3`：提交时读取最新链、校验可用审批人、写入步骤快照和 `pending_approval` 状态。
5. 新增 v3 通用通过接口，扩展驳回、待办查询、撤回状态、请假冲突状态和步骤推进；明确禁止申请人自批和管理员越权。
6. 保持 v1/v2 审批端点和状态行为不变，补齐跨版本回归测试。
7. 重构管理端审批规则类型与草稿状态，使用步骤数组实现添加、删除、上移、下移和角色选择。
8. 管理端增加 `pending_approval` 展示与通用审批动作，更新申请提交提示和审批链展示。
9. 按可见功能发布规范提升后端与管理端版本号。
10. 完成全量检查并人工核对示例链“助理 → 行政主管 → 运营负责人”的保存、提交、逐级通过和驳回。

## Required Regression Coverage

- 旧单步规则幂等迁成一步审批链。
- 多级规则读取、替换、顺序调整、空链和重复角色校验。
- 草稿按提交时最新规则生成 v3 步骤。
- 工单加班入口生成相同的配置审批链。
- 调休代理人步骤位于角色审批链之前；请假不生成代理人确认步骤。
- 前一步通过后才激活下一步，越级审批失败。
- 同角色任意一人处理后其他人不能重复处理。
- 申请人自批失败；管理员未被配置时越权失败。
- 缺少可用审批人时提交失败并指出角色。
- 任一步驳回后流程终止。
- 设置变更不影响已经提交的申请。
- v1/v2 历史申请审批、撤回、驳回和待办查询保持通过。

## Risk and Rollback Points

- 数据迁移：不能删除或改写旧单步表；新表初始化必须可重复执行。
- 状态扩展：所有依赖待审批状态的查询、撤回、冲突判断和前端标签必须同步加入 `pending_approval`。
- 授权扩展：通用接口必须以数据库当前 `pending` 步骤为准，不能只信任请求状态或前端角色。
- 直接加班入口：它绕过草稿提交路径，必须单独纳入回归。
- 回滚前确认没有只能由已撤回代码处理的 v3 进行中申请。
