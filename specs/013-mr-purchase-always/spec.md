# 013 MR 采购流转：签核通过一律流转采购，公司料号全品项必填

## 背景

原规则（2026-09-08 佬裁决）：签核通过时若全部品项无外部供应商（未填或敦阳/敦沪内部承担），系统自动标记"无需采购"（`purchase_status=skipped`），不派采购待办。

采购反馈的实际工作口径：**采购只看品项有没有厂商**——

- 有厂商：要填公司料号 + 采购单号
- 没有厂商（含 0 成本、内部承担）：也要填公司料号，只是不用填采购单号

自动跳过导致这些单永远到不了采购手上，**公司料号缺失**（如生产单 ABA2600007）。佬决定（2026-09-17）：取消签核时的"无需采购"自动判断，所有签核通过的 MR 一律流转采购，由采购按上表口径执行。

## 规则

1. **签核通过 → 一律 `purchase_status='pending'` 并派采购待办**，不再按供应商自动跳过。
   - "有合同但合同编号未填"的挂起逻辑（`waiting_contract` → 助理补编号 → 流转采购）保留不变。
2. **采购提交校验（按品项）**：
   - 公司料号：**所有品项必填**（含无厂商、0 成本、敦阳/敦沪内部承担）
   - 采购单号：仅有外部供应商（vendor 非空且非内部承担）的品项必填
   - 出货单号：所有品项选填
3. **内部承担口径不变**：vendor 含 `敦阳|敦陽|stark|dunyang|敦沪|dunhu` 视为内部承担，无外部下单对象，不强制采购单号。
4. `skipped`（无需采购）状态不再产生，仅保留历史单展示。
5. **历史补数据**：生产库 ABA2600007（id=18，`skipped`）置为 `pending` 并清空自动备注；调度器 `reconcilePendingPurchaseAssignments`（每分钟）会自动补派采购待办，无需专门脚本。

## 影响面

| 文件 | 改动 |
|---|---|
| `backend/src/modules/mr/lib/controller.js` | 签核通过不再算 needsPurchase/自动 skipped，一律派采购；submitPurchase 校验改为料号全必填 + 外部厂商品项采购单号必填 |
| `frontend-admin/src/packages/mr/lib/MrPurchaseCard.tsx` | 提交前端预检（料号全填、外部厂商品项采购单号必填）；卡片说明文案更新 |
| `backend/src/modules/mr/lib/domain.js` / `form-logic.ts` | 内部供应商正则不动（仍用于采购单号必填判定与"无需采购"行内展示） |

## 验收标准

1. 品项全部无厂商（或敦阳/敦沪内部承担）的 MR 签核通过后，采购收到待办（原来会跳过）。
2. 采购提交时：任一品项缺公司料号被拒并提示；有外部厂商的品项缺采购单号被拒；内部承担/无厂商品项无采购单号可正常提交。
3. 生产库对 id=18 执行 `UPDATE mr_orders SET purchase_status='pending', purchase_note=NULL WHERE id=18` 后，1 分钟内采购待办自动出现。
4. 存量 `done`/`skipped` 单展示无变化；waiting_contract 挂起流程无变化。
