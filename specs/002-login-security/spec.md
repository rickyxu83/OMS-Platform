# Feature Specification: 登录安全增强（生物识别通行密钥 + 微信扫码登录）

**Feature Branch**: `002-login-security`

**Created**: 2026-08-24

**Status**: Draft

**Input**: User description: "我准备给这个项目增加登录安全功能，比如说手机的 Face ID、Touch ID，安卓的指纹密码、人脸验证，或者微信扫码登录，你帮我策划一下。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通行密钥（生物识别）登录 (Priority: P1)

员工在常用设备上（iPhone Face ID、Mac Touch ID、安卓指纹/人脸）登记一次「通行密钥」后，之后登录管理端不再输密码：登录页点「通行密钥登录」（或输入框自动唤起系统通行密钥选择器），系统弹出原生生物识别，刷脸/按指纹即完成登录。

**Why this priority**: 用户点名的 Face ID / Touch ID / 安卓指纹 / 安卓人脸**四者由 WebAuthn 一套标准全覆盖**，一次实现全端受益；不依赖任何外部厂商账号体系（不需要企业微信资质），是投入产出比最高的主体功能。

**Independent Test**: 在测试服用一台 iPhone 和一台安卓机分别登记通行密钥并独立完成登录全流程，即使微信扫码（US2）完全不做，本故事也可单独交付价值。

**Acceptance Scenarios**:

1. **Given** 员工已用密码登录管理端，**When** 在「我的设置」中登记通行密钥并完成一次生物识别，**Then** 该设备生成通行密钥并出现在「已登记设备」列表中
2. **Given** 员工在某设备已登记通行密钥，**When** 在登录页输入邮箱/别名点「继续」（账号框自动填充选中亦可），**Then** 系统直接唤起生物识别，通过后进入工作台，全程不见密码框
3. **Given** 员工从未登记通行密钥，**When** 输入邮箱/别名点「继续」，**Then** 页面展开密码框走传统密码登录（不提示该账号是否登记过密钥）
4. **Given** 员工换了新手机，**When** 用密码登录后删除旧设备的通行密钥，**Then** 旧设备上的通行密钥即刻失效

---

### User Story 2 - 微信扫码登录 (Priority: P2)

员工首次在设置中绑定自己的**个人微信**后，登录页出现「微信扫码登录」入口：登录页展示微信二维码，用手机个人微信扫码并在手机上确认，即完成登录，不输密码。

**Why this priority**: 公司无企业微信，绑定个人微信。个人微信扫码登录 PC 网站只有三条官方路径（见下），均依赖公司主体的微信侧资产与审核，存在外部前置条件，故排 P2。

**通道选型（产品决策点 1，三选一）**：

| 方案 | 体验 | 成本与前置 |
|---|---|---|
| **A. 微信开放平台「网站应用」扫码（推荐）** | 与主流网站一致的「扫码→手机点确认」 | 微信开放平台企业认证 300 元/年 + 网站应用审核（要求域名已 ICP 备案） |
| B. 认证服务号带参二维码 | 扫码后若未关注需先关注，关注/扫码事件驱动登录 | 服务号认证 300 元/年 + 需维护公众号服务器回调 |
| C. 小程序码扫码确认 | 扫码打开小程序再点确认，多一步 | 小程序注册免费（企业主体）+ 需开发一个极简确认页小程序并过审 |

**Independent Test**: 微信侧资产与配置就绪后，绑定 + 扫码登录全流程可独立验证；不通时 US1 不受影响。

**Acceptance Scenarios**:

1. **Given** 员工已用密码登录，**When** 在「我的设置」选择绑定微信并按提示用个人微信扫码确认，**Then** 内部账号与该微信身份（openid/unionid）完成绑定
2. **Given** 员工已绑定微信，**When** 在登录页选择微信扫码登录并用个人微信扫码、手机上确认，**Then** 登录成功进入工作台
3. **Given** 员工未绑定微信，**When** 扫码确认，**Then** 页面提示「该微信身份未绑定内部账号」并引导先用密码登录后绑定
4. **Given** 员工微信更换，**When** 在设置中解绑（或由管理员清除绑定），**Then** 原微信身份无法再登录本系统

---

### User Story 3 - 登录安全审计 (Priority: P3)

管理员能在审计日志中看到每次登录使用的方式（密码 / 通行密钥 / 微信扫码）、时间与结果（成功/失败及原因），异常登录可追溯。

**Why this priority**: 新登录方式扩大了登录面，审计是安全闭环的兜底；但不阻塞前两者的使用价值。

**Independent Test**: 分别以三种方式成功/失败登录，审计日志各自留痕且字段完整。

**Acceptance Scenarios**:

1. **Given** 任意用户以任意方式登录成功或失败，**When** 管理员查看审计日志，**Then** 能看到登录方式、结果、时间、IP 的记录
2. **Given** 通行密钥被删除或微信被解绑，**When** 查看审计日志，**Then** 绑定关系变更也有留痕

---

### Edge Cases

- 员工设备不支持 WebAuthn（老旧浏览器/非 HTTPS 环境）：登录页不显示或禁用通行密钥入口，密码登录不受影响
- 生物识别连续失败/用户取消：系统级弹窗自身处理，页面停留在登录页并允许改用密码
- 同一员工多台设备：允许登记多个通行密钥，逐个命名与管理（如「我的 iPhone」「公司 Mac」）
- 通行密钥登录时账号被停用/锁定：与密码登录一致的拒绝口径（统一「用户名或密码错误」类模糊提示，不泄露账号状态）
- 微信扫码的 state 票据过期或被篡改：拒绝登录并要求重新扫码
- 微信侧资产未就绪（未认证/未审核通过）：微信扫码入口整体隐藏，其余登录方式不受影响
- 员工忘记密码且未登记任何替代登录方式：维持现有管理员重置密码流程，本功能不改变该兜底

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 保留现有「邮箱/别名 + 密码」登录作为兜底方式，新登录方式均为增量可选
- **FR-002**: 已登录用户 MUST 能在「我的设置」中登记基于 WebAuthn 的通行密钥（覆盖 iOS Face ID、macOS Touch ID、安卓指纹/人脸等平台认证器）
- **FR-003**: 同一用户 MUST 支持登记多台设备的多个通行密钥，并可逐个查看（设备名、登记时间、最近使用时间）与删除
- **FR-004**: 登录页 MUST 采用 identifier-first 单框流：先收集邮箱/别名，有通行密钥的账号自动唤起生物识别；浏览器支持时 SHOULD 支持通行密钥自动填充（conditional UI）
- **FR-005**: 通行密钥登录成功后的会话形态 MUST 与密码登录一致（同一 JWT HttpOnly Cookie、同等 12h 时效）
- **FR-006**: 已登录用户 MUST 能绑定/解绑个人微信身份；绑定关系与用户账号一一对应（一个微信身份同一时间只能绑一个内部账号）
- **FR-007**: 登录页 MUST 提供微信扫码登录入口；扫码确认后若身份已绑定则直接登录，未绑定则给出明确引导
- **FR-008**: 新登录方式的端点 MUST 施加与现有登录一致的限流；登录失败 MUST NOT 泄露账号是否存在/被锁定
- **FR-009**: 登录成功/失败、通行密钥增删、微信绑定变更 MUST 写入现有审计日志
- **FR-010**: WebAuthn 依赖 HTTPS；非安全上下文（如纯 IP 访问）MUST 自动隐藏相关入口且不报错

### Key Entities *(include if feature involves data)*

- **通行密钥（Passkey）**: 归属于某用户的某台设备；含凭据标识、公钥、签名计数器、设备名、登记/最近使用时间
- **微信身份绑定（WeChat Identity Binding）**: 内部用户与企业微信身份的绑定关系；含外部身份标识、绑定时间、最近登录时间
- **登录挑战（Login Challenge）**: 一次通行密钥登记/登录或扫码登录流程的短期有效凭据，防重放

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登记通行密钥的用户在手机上完成一次登录 ≤ 10 秒（从打开登录页到进入工作台）
- **SC-002**: 通行密钥登录在 iOS Safari、macOS Safari/Chrome、主流安卓浏览器（Chrome/厂商自带）三类环境各至少 1 台真机验证通过
- **SC-003**: 已绑定微信的用户扫码登录全流程 ≤ 20 秒（含手机上点确认）
- **SC-004**: 三种登录方式的成功/失败在审计日志 100% 留痕
- **SC-005**: 未登记任何新登录方式的用户，密码登录路径与现状零差异（回归零影响）

## Assumptions

- 目标端为**管理端**（frontend-admin），它是全部内部角色（含工程师工单填写）的统一登录入口；用户端站点不在本期范围
- 生物识别登录采用 WebAuthn 通行密钥（passwordless 第一因子），**不是**在密码之上再加一道二要素（2FA 不是本期目标）
- 微信扫码默认走**微信开放平台「网站应用」扫码**（方案 A，与主流网站体验一致）；前置条件为公司主体完成开放平台企业认证（300 元/年）且网站应用审核通过（要求域名 ICP 备案）。若佬选择服务号或小程序路径，契约层仅需替换微信身份获取环节，绑定关系与登录签发不变
- 生产与测试服均为 HTTPS 有效域名（WebAuthn 硬要求），localhost 开发环境天然豁免
- 企业内部系统，不关心设备证明（attestation），只信任平台认证器密钥对本身
- 现有用户表、JWT 会话、审计日志、限流中间件、MySettingsDialog 组件均可复用，不推倒重来
