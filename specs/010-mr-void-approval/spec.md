# MR 作废流程改造：申请-审批-周知三段式

## 背景与目标

现状：MR 单作废为一步到位操作，`canVoid` 允许 admin / 运营负责人 / 业务主管无条件作废已通过的 MR 单，业务负责人与对应助理可作废本人相关单。

问题：作废缺乏审批与周知机制，采购可能在不知情下继续采购动作，作废决策无留痕审批。

目标：作废改为「申请 → 审批 → 生效 → 周知」三段式流程，按采购进度分两条审批路径；发起即锁单、发起即通知采购；审批（含驳回）全程留痕留理由。

## 需求规格

### 场景一：采购未完成（purchaseStatus ≠ done）

1. **发起权限**：仅该单业务负责人或对应助理可见作废入口。
   - 业务主管只能发起自己作为业务负责人的单，无权作废他人单。
   - admin、运营负责人无任何作废权限（取消原有无条件作废特权）。
2. **发起瞬间**（填写作废原因提交后）：
   - 单据立即锁定：禁止编辑、采购、撤回等一切操作，等待审批结果。
   - 邮件通知业务主管（请求审批）。
   - 邮件通知采购（知悉：该单进入作废审批，暂停采购动作）。
3. **业务主管审批**：
   - 同意 → 作废生效 → 撤销未完成采购任务（保留现有逻辑）→ 邮件周知：签核链所有签核人（业务主管本人除外）+ 采购（结果同步）。
   - 驳回 → **必须填写驳回原因** → 单据解锁恢复原状 → 邮件通知发起人与采购，**邮件中包含驳回原因**，采购据此判断是否继续采购。单据可重新发起作废申请。
   - 跳过自审：发起人本身是业务主管（作废自己名下的单）→ 提交即生效，不走审批环节；发起瞬间同样锁单并通知采购，生效周知照发。

### 场景二：采购已完成（purchaseStatus = done）

1. **发起权限**：仅采购可见作废按钮（业务、助理、业务主管、admin、运营负责人均无入口）。
2. **发起瞬间**：填写作废原因提交 → 单据锁定 → 邮件通知行政主管（请求第一级审批）。
3. **两级审批**：
   - 行政主管通过 → 邮件通知业务主管（请求第二级审批）→ 业务主管同意 → 作废生效 → 邮件周知签核链除业务主管外所有签核人。
   - 任一级驳回 → **必须填写驳回原因** → 单据解锁恢复原状 → 邮件通知采购（发起人），**邮件中包含驳回原因**。可重新发起申请。
4. 两级审批期间全程锁定。

### 共通规则

- 作废申请、审批驳回均必填原因（作废原因沿用 `void_reason`，驳回原因新增字段）。
- 发起即锁定，审批通过前单据冻结。
- 「业务主管」审批人定位：取该单签核链「处级单位」步骤的实际签核人。若签核链无此步骤（业务主管本人发起的单），视同跳过自审直接生效。
- 审批通过作废后，归档作废 PDF、取消通知队列等现有 `voidOrder` 副作用全部保留。
- 权限目录 `mr.void` 角色列表同步收窄：移除 admin、operations_director；场景二采购发起需新增权限或复用 `mr.void` 授给 purchaser。

## 前端改动

- MR 详情页作废按钮显隐按新规则：场景一看身份（业务负责人/对应助理），场景二仅采购。
- 作废按钮点击后弹窗填原因（复用现有 decision dialog），提交后进入「作废审批中」状态展示。
- 业务主管 / 行政主管视角：详情页出现「同意作废 / 驳回复核」操作区（驳回必填原因）。
- 状态标签新增「作废审批中」。

## 非目标

- 不改变 MR 签核主流程（approval steps）。
- 不改变已作废单的「复制为新草稿」等现有功能。
- 不涉及工单（service-orders）与考勤（attendance）的作废逻辑。
