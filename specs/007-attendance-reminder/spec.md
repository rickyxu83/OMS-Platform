# Spec: 假勤审批催办（员工手动催办 + 超时自动提醒）

**Date**: 2026-09-03 ｜ **Status**: 待佬确认

## Type

Change

## 背景与产品裁决（佬 2026-09-03）

市面假勤产品（钉钉/飞书）标配催办能力，咱目前缺失：申请交上去后员工只能干等，审批人没有超时感知。佬批准做催办机制。

现有设施全部可复用：邮件发送走 `attendance_email_notifications` 队列（重试 5 次 + stale 回收），定时任务走项目调度器（安装工单主管通知同款）。

## Goal

1. 员工对「审批中」的申请可一键「催一下」，当前待审环节的审批人收到提醒邮件
2. 申请停留超过阈值无人审，系统自动提醒当前审批人，且不骚扰（有重提醒间隔）
3. 催办行为留痕（谁催的、什么时候、催的哪一步），防滥用可审计

## Scope

### A. 员工手动催办

- 「我的申请」列表：状态为 pending_* 的申请行新增「催一下」按钮（操作列，小尺寸 outline 按钮）
- 点击 → 确认 toast/对话框（避免误触）→ 后端给**当前 pending 环节的审批人**发催办邮件
  - delegate 环节 → 发给代理人本人；role 环节 → 发给该环节对应角色收件人（复用现有通知的收件人解析）
- **防骚扰**：同一申请 24 小时内只能催一次（按钮置灰 + tooltip 提示"已于 HH:mm 催过"）
- 邮件文案：复用考勤通知模板风格，主题「【假勤】催办提醒：XX 的请假申请待您审批」，正文含申请人/类型/时间范围/已等待时长/审批链接

### B. 超时自动提醒

- 调度器定时扫描（每小时一次）：当前环节停留超过 **24 小时**的 pending 申请 → 给当前环节审批人发提醒邮件
- 自动提醒与手动催办共用同一队列设施；自动提醒间隔同样 24 小时（同一申请同一环节最多一天一封）
- 终态（approved/rejected/withdrawn/void）立即停止提醒

### C. 留痕

- `attendance_requests` 惰性迁移新增两列：`last_reminded_at DATETIME NULL`、`last_auto_reminded_at DATETIME NULL`（遵循项目 ensure* 惰性迁移约定）
- 月度报表/申请明细不新增列展示（留痕仅供排查，审计需要时查库）

## Non-goals

- 不做 IM/企业微信推送（邮件为准，后续有刚需再加渠道）
- 不做审批人休假期间待审批自动转代理（未批准方向，另议）
- 不做催办次数统计报表
- 阈值 24h 先写死常量；佬要可调再进考勤设置（不阻塞本版）

## Behavior

- 手动催办：仅申请人本人 + 申请处于 pending_* 才可用；24h 内重复点击返回"已催过，请稍后再试"
- 自动提醒：以当前环节进入 pending 的时间（或上次提醒时间）起算满 24h 触发；环节流转后计时重置
- 催办/提醒不影响审批流本身，纯通知
- 邮件队列失败重试沿用现有 MAX_ATTEMPTS=5 策略

## 验证

- 后端 `npm test` + `npm run check`
- 造一条 pending 请假单：点催办 → 审批人收到邮件 → 24h 内再点被拒；库表 `last_reminded_at` 有值
- 把申请当前环节时间改到 25h 前 → 手动触发调度器扫描 → 收到自动提醒邮件
- 前端 tsc 0 错误 + build 通过；版本号按可见变更提升
- 部署 rn 由佬验收（核对邮件文案与频率感受）
