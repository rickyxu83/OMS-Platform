# Spec: 特休额度公式化（入职日期 = 年假起算日 + 可配置档位表）

**Date**: 2026-09-02 ｜ **Status**: v2 修订（佬提供现行规则图片）待佬确认

## v2 修订说明（2026-09-02，佬提供 Excel 规则图）

现行规则为**多方案 + 递增封顶尾档**模型，单表平铺档位不够：

| 方案 code        | 名称      | 适用                            | 档位                                                                           |
| ---------------- | --------- | ------------------------------- | ------------------------------------------------------------------------------ |
| `mainland`       | 陆籍      | 所有陆籍                        | 满1年 5天 / 满3年 7天 / 满5年 10天 / 满10年 15天 / 满20年起 每年+1天、封顶30天 |
| `taiwan`         | 台籍·常规 | 除特批外的台籍                  | 满1年 15天 / 满20年起 每年+1天、封顶30天                                       |
| `taiwan_special` | 台籍·特批 | 仅 Jack、Adoflo（行政手工指定） | 满0年 15天 / 满3年 18天 / 满5年 22天 / 满10年 22天起 每年+1天、封顶30天        |

- 员工归属方案复用现有 `annual_leave_rule` 字段（默认随籍别，编辑对话框可独立改成特批方案）
- 档位表加 `scheme_code` + `plus_per_year`（每年加）+ `max_days`（封顶）三列
- **下一年的计算公式佬另外给**，本期只做当年档位与建议额度

## v3 追加（2026-09-03，佬提供年末折算与调休清零规则）

### 特休年末折算

- **12-31 晚系统自动折算入账**（调度任务 23:50，幂等防重）：剩余特休余额 × 折扣（台籍·特批 0.6，其他所有人 0.5），结果**向下取整到 0.5 天**（特休最小请休单位为半天，零头不足半天抹掉、超过半天算半天）
- 折算余额**结转次年并与新档位额度叠加**（台账差额调整天然支持）
- 台账 action `year_end_carryover`，note 记录「剩余 X 天 × 0.5 → Y 天（结转次年）」
- **预览常驻**（佬拍板：不只年底前几天，一直显示）：余额控制台与员工申请页实时显示「当前余额 X 天 × 0.5 → 年末结转 Y 天」

### 调休季度清零

- 当季的调休必须在**下一季度末**前用完，否则清零：Q 季入账的调休，Q+1 季末（3-31 / 6-30 / 9-30 / 12-31）到期
- 调度任务每日 23:55 检查是否季末，是则执行清零（幂等）：按 FIFO 口径计算 Q 季入账剩余 = max(0, Q季入账 − max(0, 期间使用 − Q初结余))
- 台账 action `comp_expire`，delta 为负，note「Q3 调休到期清零 X 小时」
- 预览：余额控制台与申请页显示「本季入账剩余 X 小时将于 Q末 清零」
- 行政手工 adjust 入账的调休不参与过期（非季度入账）

## 背景与产品裁决（佬 2026-09-02）

- **复用现有「入职日期」字段作为年假起算日**，不加新字段（该字段目前仅展示与报表过滤，不参与任何计算）
- **满年对齐自然年底**：入职 Y0 年（不论几月）→ Y0+1 年 12 月底满一年 → 从 Y0+2 年 1 月起享受「满 1 年」档额度。即 **当前年档位年限 = 当前年份 − 入职年份 − 1**，负值按 0 计
- **离职再入职**：正常人重新入职 → 行政把入职日期改成新入职日，重新计算；个别需累计工龄的特殊员工 → 行政把入职日期**手工往前推**（新入职日 − 之前累计工龄），一次性特殊处理，系统不建多段任职履历
- 各假别额度独立：特休扣特休余额、调休扣调休余额，其他假别不占任何系统额度（现状已如此，spec 004 已对齐展示）

## Goal

特休年度额度从"行政拍脑袋初始化"升级为"公式给建议值、行政确认入账"：

1. 员工档案按入职日期实时显示当前档位年限（满 N 年）
2. 年假档位表（满 N 年 → 年度天数）可配置，行政在考勤设置里维护，政策/公司规则变化不改代码
3. 余额控制台为每个员工显示"按公式建议额度"，一键带入初始化/调整，入账动作仍由行政确认

## Scope

- 新表 `attendance_annual_leave_tiers`（惰性迁移）：`scheme_code VARCHAR(32)`、`min_years INT`、`days DECIMAL(4,1)`（基础天数）、`plus_per_year DECIMAL(3,1) NULL`（超出档位起点后每年加天数）、`max_days DECIMAL(4,1) NULL`（封顶）、`note VARCHAR(200)`；UNIQUE (scheme_code, min_years)；seed 上述三方案九档
- 年末/季末结算：台账新 action `year_end_carryover`（特休折算）与 `comp_expire`（调休清零），均无 request_id；两任务幂等（按年份/季度检查已有记录跳过）
- 调度：`50 23 31 12 *` 特休年末折算；`55 23 * * *` 调休季末清零（代码内判断是否季末日）
- 方案清单写死代码（mainland/taiwan/taiwan_special），label 由代码提供；员工方案 = `annual_leave_rule`，非法值回退 mainland
- 后端 API：
  - `GET /attendance/annual-leave-tiers`（考勤读权限）
  - `PUT /attendance/annual-leave-tiers`（`attendance.manage`，整表替换，事务内删旧插新）
  - 员工列表/档案 payload 增加 `annualLeaveTierYears`（按年底对齐规则计算的档位年限）与 `annualLeaveSuggestedDays`（按档位表匹配的建议额度，取 min_years ≤ 档位年限 的最大档）
- 前端：
  - 员工与余额 tab：员工行/编辑对话框展示「档位年限 + 建议额度」（如"满 3 年档 · 建议 5 天/年"）；入职日期字段说明文案补「年假起算以此日期为准，特殊累计工龄员工由行政手工调整」
  - 余额控制台：初始化/调整时显示建议额度，一键带入按钮；建议值与现值不一致时高亮
  - 考勤设置：「假别管理」旁档位表编辑区（或并入假别管理卡片内独立小节，待实现时按版面取优）

## Non-goals

- 不加「年假起算日」独立字段（佬裁决复用入职日期）
- 不建多段任职履历表（特殊员工手工调整入职日期，一次性）
- 不做额度自动入账/自动年度重置（入账始终行政确认动作）
- 不做 1 月档位跨年提醒邮件（后续有刚需再加）
- 当年入职/满年当年的折算（按月比例折算等）——档位表口径即全年额度，当年是否折算由行政初始化时自行把握

## Behavior

- 档位年限公式：`tierYears = max(0, 当前年份 − 入职年份 − 1)`；入职日期为空 → 不显示档位
- 建议额度匹配：员工方案内 `min_years ≤ tierYears` 的最大档；`建议 = days + plus_per_year × (tierYears − min_years)`，有 `max_days` 则封顶；无匹配 → 建议 0
- 档位表校验：min_years 为 0~100 整数且方案内唯一、days > 0、plus_per_year ≥ 0 可空、max_days > 0 可空；至少保留一行
- 改档位表/改入职日期即时影响建议值展示，**不追溯改动已入账余额**

## Contracts

- DB：`attendance_annual_leave_tiers (id, min_years UNIQUE, days, note, created_at, updated_at)`
- API：如上；员工 payload 增加 `annualLeaveTierYears`、`annualLeaveSuggestedDays`

## 风险与回滚

- 纯增量：新表 + 展示/建议值，不改台账写入路径；回滚代码即可，表留存无害
- 回归点：员工列表 payload 新字段不影响现有渲染；报表 hire_date 过滤逻辑不动
