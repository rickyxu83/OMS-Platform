# Spec: MR 报价识别准确率提升（回归台架 + HPE 配置组收敛 + 税拆分自动化）

**Date**: 2026-09-09 ｜ **Status**: P0 已上线 RN 待验收；P1 规则教练已确认动工 ｜ **关联**: GitHub Issue #86

## Type

Change

## 背景：语料基线（2026-09-09 从 RN 测试服拉取）

测试服积累的 MR 单是最好的规则来源——每条人工纠错都是「识别结果 vs 佬实际要的」对照样：

| 语料                           | 数量                           |
| ------------------------------ | ------------------------------ |
| 报价原始文件                   | 154 份（Excel 为主，PDF 20+）  |
| 带人工修正 ground truth 的文件 | 63 份（37 个不同内容，去重后） |
| 纠错 diff 记录                 | 87 条                          |

**失败模式基线**（cached 模式，识别原文 vs 人工修正）：

1. **HPE 整机 CTO 配置组**（最严重）：`dunyang 26-8-7 380 4516y.xlsx` 识别 0 品项→人工录 2 项；`副本ANNIE 26-8-20 360 5515_.xlsx` 识别 36 行 BOM→人工收敛 2 项。两份都有完整人工标准答案，即 Issue #86 的目标场景
2. **vendor 漏填/全称未收敛别名**：35 处（如 `""→"紫光"`、`"苏州聚盛网络技术有限公司"→"聚盛"`）
3. **含税价人工拆未税单价**：14 处（4100→3628.32 ÷1.13 类），有规律可自动化
4. 价格清零（338 处）大概率是工作流动作而非识别错误，不计入识别准确率口径

**注意**：语料含真实供应商价格，`backend/tests/fixtures/quotations/` 已 gitignore，**永不提交**。

## Goal

1. 识别准确率可量化、可回归：每次改 prompt/解析器前跑台架，红灯防劣化
2. HPE CTO 捆绑报价单按配置组收敛为整机品项（Issue #86），BOM 入 `components[]`
3. 规则教练：销售用自然语言向 AI 描述期望效果，满意后沉淀为全局规则，同类文件自动应用

## Scope

### A. 回归台架（先行，已完成主体）

- 语料落位 `backend/tests/fixtures/quotations/`（154 文件 + manifest.local.json + ground-truth.local.json）
- 快照回归复用现有 `quotation-fixtures.test.js`（153 份已学金样，纳入 `npm test`）
- 新增 `backend/scripts/mr-quote-accuracy.js`：ground truth 比对报告
  - `cached` 模式：测试服缓存识别原文 vs 人工修正（AI 文件也能评估，不重跑）
  - `replay` 模式：当前代码重跑确定性路径 vs 人工修正（评估代码改动效果）
- **验收**：基线报告已产出（本 spec 背景节数字）；后续每次 P0/P1 改动附前后对比

### B. P0：HPE 整机 CTO 配置组收敛（~~Issue #86 四层方案~~，2026-09-09 佬裁决撤回）

**已撤回**：配置组收敛专用通道（quotation-config-groups.js）曾实现并上线 RN（两份 HPE 金样验证通过：dunyang 单 0→2 整机品项、ANNIE 单 36 行 BOM→收敛），但佬裁决「HPE 不确定每份报价单都这样，先拿掉，后面有这种情况再说」——样本不足不为单一格式开专用通道，代码已移除（git 历史可查），此类场景今后由规则教练处理。

**v2 引擎最终形态**（佬 2026-09-09 裁决）：**全格式 AI 优先识别**，规则解析降级为 AI 不可用/无结果时的兜底；v1 行为完全不变。识别方式在预览「识别方式」列可见（AI 文本/AI 视觉），AI 与系统品项数不一致照旧告警。

### C. P1：规则教练（会话式规则沉淀，佬 2026-09-09 拍板）

**背景决策**：规则不由设计者预置，从销售修正动作的现场长出来——销售用自然语言向 AI 描述问题与期望效果，多轮对话调优直到满意，最终蒸馏为持久规则。销售个人层不做（规则全局共享）；打印/归档 PDF 保持全量明细不动，摘要类规则只影响屏幕展示。

**交互流**：

1. 校对预览页加入口「效果不对？告诉 AI」（文件级）
2. 对话窗：左侧当前识别结果（品项表），右侧聊天框
3. 销售大白话描述 → AI 回复理解 + 输出「变换指令」（JSON）→ **后端代码执行变换**（LLM 不直接碰数据）→ 预览即时刷新，**对话窗内同步展示变更明细卡（第几项/哪个字段/改前→改后）**，可「撤销上一步」
4. 多轮调优满意后点「沉淀为规则」→ AI 把会话蒸馏为规则卡 → 销售确认 → 入库生效
5. 会话过程全程不落库，仅沉淀时写规则表

**规则卡两种形态**（蒸馏时优先生成结构化，能用结构化动作表达的不许产提示词规则）：

- 结构化规则：`{scopeType, scopeValue, actionType, params}` → 后端规则引擎确定性执行（可单测可回归）；初版动作：组件摘要（summarize_components）、字段改写（item_edit，白名单字段 name/description/part_no）
- 提示词规则：rule_text 片段，识别时注入 AI prompt（带作用域条件，AI 条件式应用）；靠台架语料回归兜底

**作用域**：品类（服务器/网络设备…）/ 供应商 / 全局；由 AI 从会话推断 + 销售确认。

**治理**：`mr_recognition_rules` 表（惰性迁移）：scope_type/scope_value/action_type/params/rule_text/source/enabled/match_count/created_by；设置页维护列表（启用/停用/删除/命中统计），与 mr_layout_rules 同语义。

**验收**：拿 HPE 单走全流程——识别出整机品项 → 对话「只要 CPU 内存硬盘」→ 预览即时变摘要 → 沉淀规则 → 重新导入同文件自动应用摘要 → 设置页可见可停用。

### D. 版式档案（P2，顺延）

学习锚点从「文件名模式」迁移到「供应商归一化 + 表头签名」（佬指出同文件复用无价值、文件名是弱 key）；mr_layout_templates 加 vendor 维度，file_pattern 降级为辅助信息。

## 不做（Non-goals）

- 不动 AI 连接配置机制（沿用 settings/env 现有逻辑）
- 不做 HPE 以外厂商的配置组模板泛化（等语料里出现第二家再抽象）
- 不做按销售个人化的规则/提示词分裂（佬裁决 2026-09-09：个人层先不管，规则全局共享）
- 摘要类规则不改打印/归档 PDF（打印保持全量明细）
- 不预置品类按钮（如固定「精简明细」按钮）——规则由规则教练会话沉淀

## 发布策略

- feature flag 默认关 → RN 测试服手动开 → 佬验收（验收基准 = 2 份 HPE ground truth + 无回归）
- 验收通过合 main → 生产部署时 flag 保持关（灰度观察后再开）

## 风险

- AI prompt 改动全格式回归 → 用台架 replay + 快照 diff 双重卡控
- `components[]` 入库为惰性迁移加列，回滚 = flag 关闭（列留着无害）
- 规则教练：LLM 只出变换指令、后端执行，会话不落库；提示词规则注入有回归风险 → 沉淀后必须跑语料回归，劣化则停用该规则
