# Spec: 假勤模块显示层三件套（改名「假勤管理」+ 审批链时间线 + 团队请假日历）

**Date**: 2026-09-03 ｜ **Status**: 待佬确认

## Type

Change

## 背景与产品裁决（佬 2026-09-03）

考勤模块实际职责是「请假/加班/调休审批 + 额度台账 + 值班津贴」，不含打卡，「考勤管理」名不副实。佬拍板：

- 模块显示名改「**假勤管理**」（飞书 People 同款叫法）
- 审批链悬浮卡片（`StatusWithChain`，信息已全）升级为**时间线步骤条**视觉
- 新增**团队请假日历**，复用值班模块月历视图资产

## Goal

1. 用户看到的模块名与实际职责一致：菜单/标题/通知文案统一为「假勤管理」
2. 员工/审批人悬浮状态徽章时，一眼看清审批链走到哪一步、谁已审、谁卡着（步骤条视觉，不再读文字列表）
3. 主管/行政/员工能在月历上直接看到"哪天谁不在"（已批准的请假+调休）

## Scope

### A. 改名「假勤管理」（仅显示层）

- 前端显示文案：侧边栏菜单（AdminLayout）、考勤页标题（Attendance.tsx）、工作台入口、相关按钮/对话框标题、面包屑
- 通知/邮件文案中的「考勤」字样（attendance-notifications.js 与 mail.js 模板中的显示文案部分）
- 繁体文案同步（「假勤管理」→「假勤管理」，繁体写法相同，逐处确认）
- **不动**：路由 `/attendance`、权限 key `attendance.*`、API 路径 `/api/v1/attendance/*`、表名、代码内部标识——纯内部命名，改名零回归风险
- 可见变更，按规矩升版本号

### B. 审批链时间线步骤条（纯前端）

- 落点：`RequestList.tsx` 的 `StatusWithChain` 悬浮卡片内，`ChainSteps` 由文字列表升级为步骤条
- 视觉：环节节点圆点 + 连接线；`approved` 绿色打勾、`pending` 高亮（当前环节）、`rejected` 红色叉、`waiting/skipped` 灰色；节点下方显示审批人姓名 + 时间（`approvedAt`/`rejectedAt`）
- 数据字段现成（`ApprovalStep.approvedByName/approvedAt/rejectedByName/rejectedAt/rejectedReason`），无后端改动
- 驳回原因在 rejected 节点展示（hover 或节点下小字）
- 移动端：悬浮卡片在窄屏保持可读（步骤条纵向渲染）

### C. 团队请假日历（前端新视图 + 后端只读接口）

- 新 tab「团队日历」（位置：我的申请/待我审批 之后，记录与报表 之前，按版面取优）
- 月历格子视图：每格显示当天在假人员（姓名 + 假别色块，色板复用值班日历现有配色语言）
- 数据源：**已批准**（终态 approved）且日期范围覆盖当日的 `leave` + `comp_time` 申请；加班（overtime）不算"不在"，不显示
- 后端新只读接口：`GET /attendance/team-calendar?month=YYYY-MM`，返回当月每日在假条目（员工姓名、假别 code/label、起止时段、全天/半天槽位）；权限 `attendance.apply` 起（公司内部透明：所有考勤用户可见——小公司谁休假大家知道无妨；佬若要限审批权限以上再收紧）
- 月份切换只拉当月数据；当天格子高亮；半天（上午/下午）在色块上区分（半色/角标）
- 不含编辑、不含审批操作，纯只读

## Non-goals

- 不动路由/权限 key/API 路径/表名等内部标识
- 不做日历上的请假操作（申请/审批仍走原入口）
- 不做部门过滤视图（无部门建模；后续有刚需再加）
- 不做审批人休假自动转代理（未批准方向，另议）
- 催办机制不在本 spec（见 spec 007）

## Behavior

- 改名后全文检索前端显示面不再有「考勤管理」字样残留（权限说明文档、AGENTS.md 表格里的角色说明另行同步）
- 时间线步骤条：无 approvals 数据时退化为原状态徽章（兼容旧数据/加班申请无 steps 场景）
- 团队日历：申请被作废/撤回后当日不再显示；跨月申请在每个月份视图中都正确分段显示
- 日历只显示已批准终态；pending/rejected/withdrawn/void 一律不出现

- 时间线：造一条多级审批中的请假单，悬浮状态徽章核对步骤条各状态渲染
