# spec 019：MR 合约用印流程闭环

## 背景

现有流程：销售建 MR 单时选"是否有合同"，合约文件混在通用附件区上传；合同编号允许暂空，签核全过后若缺编号则采购挂起（`waiting_contract`），由助理事后补填编号——**只补编号，没有上传盖章合约的环节，且卡在采购前而非助理审批步**。

实际业务流程：销售上传**未盖章**合约 → 助理拿着合约去内部系统走用印流程 → 拿到合同号和盖章合约 → 回填 MR 后才能继续流转。

## 佬已确认的规则（2026-10-13 初版；2026-10-14 补充确认）

1. 选“有合同”时，销售提交前**未盖章合约必填**（硬校验；“有合同但合约没拟好”不豁免，选了就必须有合约文件）
2. **不动历史已签核的 MR 单**；新校验只对之后提交的单生效（在途 `waiting_contract` 旧单按老流程补编号走完，不要求补盖章件）
3. 销售提交时选了“有合同”，**邮件通知对应助理并附上未盖章合约附件**（只发对应助理，不抄送其他人）
4. 合约上传从通用附件区移入表单“合同与罚则”栏位（专用栏位）
5. 助理签核步门禁：**盖章合约 + 合同编号双齐**才能点“通过”
6. **只保留盖章合约**：助理上传盖章件后，未盖章件自动删除；驳回后改为“无合同”时，合约附件（含盖章件）自动删除

## 流程设计

```
销售填单：合同与罚则栏位
  是否有合同 ● 有合同
  合约附件   [上传未盖章合约]（必填校验）
  合同编号   可暂空（合同流程未走完）
     ↓ 提交
系统：给助理发邮件（附未盖章合约附件）→ 助理走用印流程
     ↓
助理签核步：合约栏位解锁"盖章合约"上传位 + 合同编号编辑
  上传盖章合约、填合同编号 → 点"通过"（缺一则拒绝并提示缺哪样）
     ↓
后续签核照常 → 签核通过即有编号 → 直接流转采购
（waiting_contract 后置补填流程保留，仅供在途旧单兜底）
```

## 技术方案

### 数据

- `files.quote_role` 扩展两个值：`'contract'`（销售上传的未盖章合约）、`'contract_signed'`（助理上传的盖章合约）；现有 `quote_sales`/`quote_purchase` 不变
- 字段为 VARCHAR(16)，无需表结构变更；不迁移历史附件（历史合约文件 `quote_role` 保持 NULL，留在通用附件区显示）

### 后端（backend/src/modules/mr）

1. **上传入口**：`POST /:id/attachments` 增加可选 `role` 参数（`contract` / `contract_signed`），鉴权：
   - `contract`：canEdit（销售建单/驳回修改，助理步助理编辑同现有口径）
   - `contract_signed`：助理签核步的当前签核人（含助理主管代签口径，与 canApprove 助理步一致）+ admin
2. **提交校验**（`validateSubmission` 或 submit 处）：`hasContract=1` ⇒ 必须存在 `quote_role='contract'` 附件，否则 422"请上传未盖章合约"
3. **提交通知**：submit 成功后若 `hasContract=1`，向助理（resolveStepAssignee 'assistant' 同口径）投递新 outbox 事件 `contract_seal`；`sendMrApprovalMail` 支持附件（参照 mail.js 报表附件做法，从 storage_path 读文件 Buffer 附进邮件），文案提示"请走合约用印流程，完成后回 MR 单上传盖章合约并补填合同编号"
4. **助理步 approve 门禁**（现有 `current.step_key === 'assistant'` 校验块内追加）：新流程单（存在任一合约附件）要求 ①`contractNo` 非空 ②存在 `quote_role='contract_signed'` 附件；缺一则 422，错误明细指明缺项。无任何合约附件的视为功能上线前的在途单，跳过门禁走老流程
5. **自动清理**：上传 `contract_signed` 成功后删除该单全部 `contract` 附件（DB+磁盘，文件名记入审计 `removedUnsigned`）；表单保存时 `hasContract≠1` 则删除全部合约附件（`contract`/`contract_signed`）
5. **助理步合同编号写入**：助理步编辑态本就允许改表单（canEdit 同口径），编号随表单保存即可；另要求盖章件上传不受"编辑模式"开关限制（见前端 3）
6. **审计**：盖章件上传记 `audit_logs`（action `contract_signed_upload`）；编号变更复用表单保存的现有审计口径
7. `waiting_contract` 相关逻辑（`canFillContractNo`、`submitContractNo`、`MrContractNoCard`）**保留不动**，给在途旧单兜底

### 前端（frontend-admin/src/packages/mr）

1. **"合同与罚则"栏位**加"合约附件"上传位：
   - 编辑态（销售/助理步编辑）：可传/删 `contract` 件；选"无合同"时隐藏并提示已有合约附件需先删除（或自动随 hasContract=0 清空——提交校验兜底）
   - 只读/审批态：显示未盖章件、盖章件（带"未盖章"/"盖章"徽标），可预览下载
2. **助理签核步**：合约栏位解锁盖章上传位 + 合同编号输入（无需进入全表编辑模式）；"通过"按钮前端预检缺项提示（后端门禁为准）
3. 通用附件区保持不变（报价等其它文件照常）；附件列表对 contract/contract_signed 件显示对应徽标
4. 合同编号 placeholder 文案更新："合同流程未走完可暂空；助理签核时补填"

### 边界与兼容

- **驳回重提**：编号与合约附件保留在单上；若驳回后改为“无合同”，保存时合约附件自动删除（前端切换时弹确认框）
- **助理主管代签**：可代传盖章件、代填编号（与代签同口径）
- **销售提交时已填编号**：编号预填可改，盖章件仍必须由助理步上传（编号不代表已用印）
- **助理传盖章件后又删除**：单据只剩未盖章件或无任何合约件，门禁继续拦截，需重新上传盖章件
- **历史单**：已签核/在途单一律不动；`waiting_contract` 在途单按老流程补编号即可通过
- **作废锁定**（`void_request_status='pending'`）期间禁止一切合约变更（沿用 isVoidLocked 现有口径）
